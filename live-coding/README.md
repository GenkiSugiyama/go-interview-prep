# ライブコーディング対策

ライブコーディングでは、**正解したかどうかと同じくらい「どう考えたか」が見られています**。
黙って10分考えて正解するより、考えを話しながら進めて途中でヒントをもらえるほうが評価は高くなりがちです。

## 基本の6ステップ

面接ではこの順番で進めると、詰まりにくく、評価もされやすくなります。

### 1. 問題を自分の言葉で言い直す（1〜2分）

> 「整数の配列と target が与えられて、足して target になる2つの要素の添字を返す、という理解で合っていますか？」

### 2. 制約・エッジケースを質問する（2〜3分）

**いきなり書き始めないことが一番大事**です。聞くことのテンプレ:

- 入力のサイズは？（→ 狙う計算量が決まる。[00_complexity](../algorithms/00_complexity/) 参照）
- 空の入力はありえる？
- 負の数・0・重複はありえる？
- 答えが存在しない場合は何を返す？答えが複数あるときは？
- 入力の配列を書き換えてもいい？
- 文字列なら: 英字だけ？大文字・小文字は区別する？日本語（マルチバイト）は？

### 3. 具体例で手を動かす（1〜2分）

小さな例を自分で作り、手で解いてみます。規則性が見つかることが多いです。

### 4. 方針を話す → 合意を取る（3〜5分）

- まず**素直な解法（ブルートフォース）と計算量**を言う
  > 「全ペアを二重ループで調べれば O(n²) で解けます」
- 次に**改善案**を言う
  > 「見た値を map に覚えておけば O(n) になります。代わりにメモリを O(n) 使います」
- 「この方針で書いてもいいですか？」と**確認してから**書く

### 5. コードを書く（10〜15分）

- 書きながら、今何をしているかを短く口に出す
  > 「ここで map に、値から添字への対応を入れていきます」
- 変数名は分かりやすく（`m` より `index`、`seen`）
- 詰まったら黙らずに、何で詰まっているかを話す。ヒントをもらうきっかけになります

### 6. テストと計算量の説明（3〜5分）

- 作った具体例で、**コードを1行ずつ手で追う**（ドライラン）
- エッジケース（空、要素1つ、答えなし）を確認する
- 最後に時間計算量・空間計算量を理由付きで言う

## 詰まったときの言い方

| 状況 | 言い方の例 |
|------|-----------|
| 方針が浮かばない | 「まずは素直な O(n²) で書いて、そこから改善を考えてもいいですか？」 |
| Go の関数名を忘れた | 「ソートの関数名がうろ覚えなので、`slices.Sort` だと仮定して進めます」 |
| バグが見つからない | 「具体例 [2, 7] で変数の値を追ってみます」 |
| ヒントが欲しい | 「map を使う方向で考えているのですが、方向性は合っていそうですか？」 |

## ライブコーディング用の Go チートシート

うろ覚えになりやすいものです。面接前に見直しましょう。

```go
import (
    "slices"
    "sort"
    "strings"
    "strconv"
)

// スライス
s := make([]int, 0, n)         // 長さ 0、容量 n
s = append(s, 1)
slices.Sort(s)                 // 昇順ソート（Go 1.21+）
slices.Reverse(s)
idx, found := slices.BinarySearch(s, 5)
sort.Slice(people, func(i, j int) bool { return people[i].Age < people[j].Age })

// 2次元スライス
grid := make([][]int, h)
for i := range grid {
    grid[i] = make([]int, w)
}

// map
m := map[string]int{}
if v, ok := m["k"]; ok { _ = v }

// 文字列
strings.Split("a,b,c", ",")    // []string{"a","b","c"}
strings.Join([]string{"a", "b"}, "-")
strconv.Itoa(42)               // "42"
n, err := strconv.Atoi("42")
var sb strings.Builder         // ループで文字列を連結するとき
sb.WriteString("abc")
sb.WriteByte('d')
sb.String()

// 最大・最小（Go 1.21+ の組み込み関数）
max(3, 5)                      // 5
min(3, 5, 1)                   // 1
math.MaxInt                    // 最大値の初期値に（math を import）

// スタック（スライスで代用）
stack := []int{}
stack = append(stack, 1)       // push
top := stack[len(stack)-1]     // peek
stack = stack[:len(stack)-1]   // pop

// キュー（スライスで代用）
queue := []int{1}
front := queue[0]
queue = queue[1:]              // dequeue
```

## 練習方法

1. [algorithms](../algorithms/) の問題を1問選ぶ
2. タイマーを **30分** にセットする
3. 上の6ステップを**声に出して**（または下のメモ欄に書きながら）解く
4. 終わったら、下の振り返りシートを書く

慣れてきたら、スマホで録音して聞き直すと、黙っている時間の長さに気づけます。

### 振り返りシート（コピーして使う）

```markdown
## 日付 / 問題名

- かかった時間:
- 制約の質問はできた？: はい / いいえ
- ブルートフォース → 改善の流れで話せた？: はい / いいえ
- 黙っていた時間が長かった場面:
- バグ・つまずき:
- 次に意識すること:
```
